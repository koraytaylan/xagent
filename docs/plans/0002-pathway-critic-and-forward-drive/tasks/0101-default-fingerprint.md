# Routes-off free-life fingerprint

## Outcome

The repository holds a committed fingerprint of one seeded free life run with both pathway routes off, and a test that re-runs that life through the built `xagent` binary and compares two digests (per-agent metrics, tick-log payload) against the recorded values. The fixture also records the GPU adapter name of the recording host. Later tasks replay this test to prove INV-1. Digests cover behaviour only, so later config and layout growth cannot change them.

## Scope

- Config fixture `crates/xagent-sandbox/tests/fixtures/pathway_routes_off_config.json`: the `--dump-config` output of plan-baseline code plus two `brain` keys, `"critic_input": "encoding"` and `"forward_pathway_enabled": false`, and nothing else. Today these keys are ignored; once route-flags defines them they pin both routes off.
- Fingerprint fixture `crates/xagent-sandbox/tests/fixtures/pathway_routes_off_fingerprint.json`.
- Test `crates/xagent-sandbox/tests/pathway_default_fingerprint.rs`: a pure verdict function and non-GPU unit tests.

## Non-goals

- No change under `crates/*/src`, config defaults, harness, CLI flags, report or log format.
- No new crate dependency. FNV-1a is implemented in the test.
- No edit to `STATUS.md`, `PLAN.md`, `ARCHITECTURE.md` or any decision record.
- Digests are never regenerated by later tasks. A later replay failure is a product defect to fix, not a reason to rewrite the fixture.
- No digest comparison on another adapter; a different adapter is a skip.

## Digest definition

- 64-bit FNV-1a: offset basis `0xcbf29ce484222325`, prime `0x100000001b3`, byte by byte with `u64::from(byte)` and `wrapping_mul`; rendered `format!("{:016x}")`.
- Metrics digest: parse the report with `serde_json`, keep only the top-level `agents` value, serialise it with `serde_json::to_vec`, hash the bytes.
- Log digest: hash only the raw log bytes after the first `\n`.

## Verdict and adapter rule

- The adapter name is parsed from the child's stderr (run with `RUST_LOG=info`) at the first `[GpuKernel] Adapter: AdapterInfo { name: "` line, the name running to the next `"`. A missing line fails the test; it never skips.
- If `GpuKernel::is_available()` (`crates/xagent-brain/src/gpu_kernel.rs`) is false, panic when `XAGENT_REQUIRE_GPU` is set, otherwise print a skip and return, as `gpu_adapter_present_when_required` does in `crates/xagent-sandbox/tests/integration.rs`. Presence is required before any adapter comparison.
- Pure `fn fingerprint_verdict(recorded: &Fingerprint, adapter: &str, metrics_digest: &str, log_digest: &str) -> Verdict`. `Verdict` is `Match`, `Mismatch { digest: &'static str, computed: String, recorded: String }` (`"metrics"` or `"log"`), or `OtherAdapter { recorded: String, actual: String }`. The adapter name is compared first, then metrics, then log.
- GPU test: `OtherAdapter` prints a skip naming both adapters and passes, even with `XAGENT_REQUIRE_GPU` set. `Mismatch` fails, naming digest, computed and recorded values. `Match` prints `fingerprint: match` and passes. The test always prints both digests and the adapter name to stderr.

## Unit tests (non-GPU, committed fixture)

- `altered_metrics_digest_is_rejected`: replaces the recorded metrics digest in memory with a different 16-digit value; expects `Mismatch` with digest `"metrics"`.
- `altered_log_digest_is_rejected`: the same for the log digest; expects `"log"`.
- `recorded_digests_match_themselves`: recorded digests and adapter give `Match`.
- `other_adapter_is_skipped`: a different adapter name gives `OtherAdapter`.

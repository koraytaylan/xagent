# Plan amendment authorizations

## 1. boundary-detail: how choose_candidate records the drawn index

- **Superseded requirement:** tasks/0201-boundary-detail.md, Decisions, "`choose_candidate` keeps its single `random_range` draw and also returns the drawn index into the chosen pool", and Step 2, "Make `choose_candidate` also return the drawn index". The superseded reading is the review finding at supervisor.rs:597 that `choose_candidate` must return `(slot, reason, drawn)`.
- **Contradiction:** the same task's Non-goals freeze every existing test body, and Done when requires the existing `supervisor::tests` to stay unchanged. The existing tests `tiebreak_death_first_and_one_slot` and `tiebreak_same_seed_same_choice` bind `let (slot, reason) = choose_candidate(..).expect(..)`, compare the result with `(usize, ReplaceReason)` and compare two calls directly. That fixes the return type to `Option<(usize, ReplaceReason)>`. A three-value tuple, a nested tuple or a wrapper type fails to compile (rustc E0369 on comparing tuples with different element types, from the implementer's evidence). So no return type meets both requirements.
- **Source-backed correction:** ARCHITECTURE.md line 30 requires only that `choose_candidate` and `plan_parent` "record the index they drew", with draw count and order unchanged. The amended Decision keeps `choose_candidate`'s name, its two-value return, its single draw and its place on the production path. It records `drawn_index` as the chosen slot's position in the chosen pool. Pool entries are distinct slots, so that position is the drawn value, and `slot == pool[drawn_index]` holds. It states that returning the index is not required. Nothing else changes: the INV-3/INV-4 tests, the other Decisions, the touches and the checks stay as they were.
- **Executable witness:** the focused-proof check (`cargo test -p xagent-sandbox --lib supervisor::tests::`). It compiles the unchanged existing tiebreak tests against the two-value return, and the INV-4 test asserts `slot == tiebreak.pool[drawn_index]` for every recorded `Replaced` detail.

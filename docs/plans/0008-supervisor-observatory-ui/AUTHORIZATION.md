## A1 - session-wiring: Live fold fan-out

- **Superseded requirement.** tasks/0402-session-wiring.md, Live fold: `observatory_record(event: &SimEvent) -> Option<ObservatoryRecord>`, a stateless fn delegating to the `From` conversions, with the drain folding a single `Some(r)` per event; ARCHITECTURE.md (session wiring paragraph): "The event drain converts each plan 0006 telemetry `SimEvent` into an `ObservatoryRecord` and folds it."
- **Contradiction.** INV-2 requires the live model to equal the browse model, so every boundary, slot, intake, progress and series record must be folded. The landed API makes that impossible under the superseded wording: `SimEvent::SupervisorTelemetry(Box<TelemetryFrame>)` (sim_runtime.rs:241) is the only telemetry variant and carries N slot standings, M intake rows, a progress record and a series point; parent-resolved boundary and slot records exist only via `ObservatoryModel::boundary_record(&self, ..)` (observatory/mod.rs:538) and `ObservatoryModel::slot_record(&self, ..)` (:517), while `From<&SourceBoundary>` (:566) leaves the parent unresolved and `fold` (:365) does not resolve it. Both files are outside the task's touches. A one-record stateless fn either drops records (breaks INV-2) or forces a second conversion path in the drain (rejected at review round 1).
- **Correction.** `observatory_record(model: &ObservatoryModel, event: &SimEvent) -> Vec<ObservatoryRecord>` is the single conversion point: one parent-resolved boundary record for `SupervisorBoundary`, every record of the frame for `SupervisorTelemetry`, empty otherwise; the drain folds each returned record and holds no other conversion. ARCHITECTURE.md reworded to match. Objective, INV-2, touches, tests, checks and task identity unchanged.

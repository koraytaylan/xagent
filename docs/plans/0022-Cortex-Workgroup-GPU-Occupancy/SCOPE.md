# Scope — Plan 0022

> Resolve whether the visual cortex's 7% GPU lane occupancy should be restructured for production GPU use, or kept permanently GPU-gated with emergence pivot to legacy raycast encoder.

## Why this plan

Current state: Plan 0017 WS0002 committed to "optimize visual-cortex throughput to bring it within the ≥50% budget (currently 0.24%)" and reported "✅ Done / ≥50% throughput budget asserted on CI," but that assertion holds only on lavapipe (software adapter). The real-GPU measurement (`docs/plans/0017-Credit-Path-And-Emergent-Visual-Evolution/CORTEX-PROFILE-BASELINE.txt`) shows cortex at ~83 tps vs ~7,625 tps baseline (~1.1%, ~93× slower) on Metal GPU hardware. The test (`cortex_throughput_meets_budget`, `crates/xagent-sandbox/tests/integration.rs:703-720`) was explicitly made to skip on real GPU with the rationale: "warp underutilization (18/256 active lanes = ~7%) makes the ≥50% criterion unachievable without workgroup restructuring (out of scope)" (`gpu_kernel.rs:492-503`). This deferred the root cause to the plan series but left the status misleading.

The 2026-06-25 forward-looking review (docs/reviews/2026-06-25-glm-52.md F2) flagged this as a **P1 gate-integrity regression**: the cortex's structural occupancy problem — not a throughput optimization opportunity — is the actual blocker for any cortex-on default, and the STATUS misleads readers into thinking ≥50% is achieved on hardware when it is not.

1. **The cortex dispatch is structurally occupancy-limited.** `coop_visual_cortex` (`brain_passes.wgsl:548+`) runs as a per-workgroup computation with `BRAIN_WORKGROUP_SIZE=256` (`brain_passes.wgsl:18`). Only `VISUAL_FEATURE_COUNT=18` threads (= `GABOR_ORIENTATIONS × GABOR_SCALES × POOL_ROWS × POOL_COLS` = `2 × 1 × 3 × 3`) compute output features per agent; the remaining `256 − 18 = 238` lanes are idle during the Gabor/pooling stages, yielding ~7% occupancy on hardware with 256-lane warps. (`common.wgsl:75-76, 133-134, 145-146`)

2. **Optimization alone (retina size, pool radius, filter count) cannot fix occupancy.** The 0017 cortex optimizations (separable DoG in WS0002) reduced per-pixel cost but not the structural lane-imbalance — the cortex still runs 18 active threads in a 256-lane workgroup. Reducing retina from 32×32 to 24×24 (0017 optimization) and DoG to separable kernels changed throughput from ~1.1% to ~1.5% (rough estimate from the profile), an additive improvement within the same structural constraint. The lane occupancy itself (18/256) is fixed by the output feature count and cannot be raised by kernel tuning alone.

3. **The emergence line is blocked on this decision.** 0017 WS0003 (emergent encoder spike) is deferred pending credit-path fixes (0018, carrying to 0019); once those unlock, the A/B (0017 WS0004, now superseded) needs the cortex throughput budget settled. If the cortex stays ~1% on GPU, it cannot ship as the default encoder path without regressing the production simulation by ~100× — the emergence line must either keep the cortex permanently gated or pivot back to the legacy raycast encoder (which has no occupancy constraint). The decision is forced by the product constraint (default encoder performance) and the scientific constraint (cannot fairly A/B a ~1% option against an emergent alternative).

**Provenance.** Every finding re-verified against the 0017 plan record: the real-GPU profile at `0017-Credit-Path-And-Emergent-Visual-Evolution/CORTEX-PROFILE-BASELINE.txt:21` (~83 tps vs ~7,625 baseline, confirmed); the hardware skip and its rationale in `cortex_throughput_meets_budget` (`tests/integration.rs:714-720`, `gpu_kernel.rs:492-503`, confirmed); the 18-lane feature count from `common.wgsl:75-76, 133-134, 145-146` (confirmed); the misleading "Done / ≥50%" STATUS row and the GLM-5.2 F2 gate-integrity flag (confirmed). No prior review claim was rejected during verification — every cited claim held.

## In scope

- **0001 — Workgroup-Occupancy-Restructuring.** Redesign the cortex dispatch to increase active lanes: explore options such as smaller-per-thread Gabor filters (e.g. reduce VISUAL_FEATURE_COUNT from 18 to match hardware lane-width or increase filter count to fill lanes), alternate memory layout (e.g. shared-memory staging for cooperative loading), or a multi-agent workgroup structure. Measure occupancy and throughput on real GPU hardware (Metal or Vulkan). If ≥50% of fused baseline is achieved and verified to hold across multiple GPU backends, assert the new budget via a hardware-aware test and declare cortex ready for default path consideration. If occupancy restructuring is too costly or doesn't reach ≥50%, record findings for the fallback decision (WS0003). See [TASKS.md](TASKS.md).
- **0002 — Occupancy-Improvement-Validation.** If WS0001 results in occupancy ≥50% on real GPU hardware, re-measure cortex throughput on Metal, AMD RDNA, and/or NVIDIA hardware (CI environment preferred). Assert ≥50% of fused baseline across all target backends. Update the 0017 cortex STATUS to reflect budget achievement and whether the encoder is now viable for default-path consideration. Record decision on whether to flip `visual_cortex_enabled` default or keep it flag-gated pending A/B results (0017 WS0004 / encoder emergence comparison). See [TASKS.md](TASKS.md).
- **0003 — Cortex-Permanence-Fallback-Decision.** If occupancy restructuring in WS0001 is infeasible, too costly, or doesn't reach ≥50% on GPU, record an explicit decision document stating: (a) occupancy remains <50% despite restructuring attempts, (b) cortex stays permanently behind `visual_cortex_enabled=false` default, (c) the emergence line pivots back to the legacy raycast encoder (0008 Hubel-Wiesel cortex is demoted from any default-path consideration; the legacy `vision_count`-wide Gabor bank or a simpler learned encoder becomes the comparison baseline), and (d) the cortex remains a complete research artifact available for off-default experimentation. Update 0017 STATUS to close the emergence roadmap with a clear defer/pivot rationale. See [TASKS.md](TASKS.md).

## Locked decisions

- **Occupancy is the load-bearing constraint, not throughput optimization.** The cortex's ~1.1% throughput on GPU is not a tuning problem (0017's optimizations reduced cost incrementally but did not change the 7% lane occupancy). It is a structural hardware-occupancy mismatch: 256-lane workgroup, 18 active threads. WS0001 must either restructure the workgroup/dispatch to increase occupancy, or accept that the cortex cannot meet a ≥50% budget on GPU. Tuning (kernel separability, retina size, pooling radius) is orthogonal to occupancy and should not be called a "fix" if occupancy remains <50%. This decision is locked by the evidence: real GPU measurement at `docs/plans/0017-Credit-Path-And-Emergent-Visual-Evolution/CORTEX-PROFILE-BASELINE.txt`.
- **Fallback is emergence pivot, not a new optimization plan.** If WS0001 does not achieve ≥50%, the cortex stays GPU-gated. The emergence line (0017 WS0003/WS0004) does not restart with a new cortex-optimization plan; it pivots to a different baseline encoder. This avoids a loop of repeated optimization attempts against a structural limit. The decision is recorded; the path forward is re-selected. Revisit gate: a structural change to how cortex is dispatched (e.g. if WGSL gains native subgroup operations that reduce the effective workgroup size) could unlock a new plan, but that would be a separate decision gate, not a carry-forward of this one.
- **Budget assertion must hold on real GPU hardware, not software adapter.** The 0017 ≥50% budget assertion currently skips on real GPU and asserts only on lavapipe (software). For this plan, WS0002 must demonstrate ≥50% on at least one real GPU backend (Metal on macOS, RDNA on Linux, NVIDIA on any platform). If occupancy rises but the assertion still doesn't hold on hardware (e.g. holds on NVIDIA but not on Metal due to backend-specific performance), the budget is deemed not met and the fallback (WS0003) is triggered. The decision is measurement-driven and backend-aware.

## Out of scope

- **Credit-path fixes and emergence encoder development.** Plans 0018–0019 carry the credit-path bottleneck (gradient structuring, direct supervision, trace timing). The encoder emergence (0017 WS0003) is deferred pending credit-path unlock. This plan resolves only the cortex occupancy constraint; the emergence A/B decision is downstream.
- **Fitness comparisons or behavioral evaluation of the cortex.** This plan measures occupancy and throughput only, on fixed config. Any fitness/steering/intent A/B (0017 WS0004 or later) is out of scope; those depend on the credit path being fixed first.
- **Retiring the 0008 cortex codebase.** The cortex implementation (Gabor kernels, DoG, pooling logic) is mathematically correct and probe-proven. Restructuring occupancy may change the filter count or feature-width constants, but the core code stays. If the fallback (WS0003) pivots to a legacy encoder, the cortex code remains available behind its flag for future research.
- **Redesigning the brain-passes.wgsl control flow or buffer layout.** The cortex is one function (`coop_visual_cortex`) inside the larger brain pass. If occupancy restructuring requires shared-memory changes (WS0001 Variant C), those are in-scope; but restructuring the entire brain-pass pipeline or moving the cortex to a separate pass is out of scope (would be a separate architectural plan).

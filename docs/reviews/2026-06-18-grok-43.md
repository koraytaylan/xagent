## Executive Summary / TL;DR

**Verdict: The mechanical implementation is largely correct, complete, and well-tested for its core goals (effort-denominated foraging/exploration, speed-invariant hazard via path-length dose, above-baseline superlinear drag, dedicated danger percept + symmetric potential shaping, intent metric, flag gating that preserves legacy behavior). Fused and split paths are symmetrically updated with identical accumulators, drag/hazard math, danger scan, respawn whitelists (including new avoidance counters), and resets. Calibration values match the decision doc exactly and are wired through. New telemetry flows through both headless and gpu_orchestration readback paths into AgentFitness / behavior_metric / DB (idempotent migrations). Integration test surface grew dramatically with falsifiable GPU mirroring, survive-respawn, sign, crossing-invariance, and calibration replay tests. Headless A/B harness + decision doc record measured decoupling (with gate criteria met per the doc).**

**However, this is not a clean landing under the project's own strict rules.** The single largest class of defects is **systematic violation of the "source must be agnostic of the planning process" rule** (CONTRIBUTING.md: "Never name an internal plan... anywhere in source: not in comments, not in doc-comments... Strip pre-existing plan/task references file-by-file as code is touched"). Dozens of "(plan 0009 ...)", "plan 0008", "speed-decoupling gate", "Layer A/B/C/D", "000x" references were introduced or left behind in **every** touched source file (config.rs, buffers.rs, gpu_kernel.rs, governor.rs, agent/mod.rs, main.rs, all WGSLs, and especially the massive test additions). Old 0008 references were not stripped on touch either. This is not a nit; it is a hard rule reinforced in Claude.md and recent reviews. The "incremental cleanup" mandate was ignored on the exact files touched by this feature.

Secondary issues:  
- Calibration test (`fitness_calibration_replay_profiles`) is a `--nocapture` print-only diagnostic, not a falsifying assertion (contrary to "Tests must be falsifiable" and CONTRIBUTING testing rules). Numbers match the decision doc, but the test would not fail if deltas regressed.  
- Minor numeric/loop-var hygiene and one long function (danger scan ~70 lines of nested loops + math, no helper).  
- Potential (unmeasured here) interaction with the brain-pass latency ceiling diagnosed in the 2026-06-15 review: the danger scan (bounded but O((radius/cell)^2) per agent) now lives inside the per-physics-tick path in the split implementation and inside the vision-cycle inner dispatch in fused; new per-tick length/adds are cheap but add to the dominant kernel cost.  
- A few short-loop vars (`dr`/`dc`) and comments with rationale that belong in commits/PRs, not source.  
- One behavior_metric column (`avoidance_intent_fraction`) added via ALTER but the original `danger_dwell_fraction` population path and some legacy fields warrant cross-checks.

**Strengths (real and substantial):** Perfect mirroring discipline between fused/split for all new logic (the plan's #1 risk); clean flag gating with documented byte-identical defaults (speed_cost_exponent=1.0, effort=false, danger_percept=false); named consts for all non-trivial numbers in fitness and many in shaders; numeric safety guards (`max(..., EPSILON)`) on every new division; telemetry readback authoritative and consistent across paths; DB uses the project's idempotent ALTER pattern; test growth exercises the new paths with GPU self-skipping; calibration discipline (doc + replay profiles match landed values); agent/mod passthroughs for locked flags are correct.

**Overall:** The feature delivers the *intent* of making fitness reward deliberate behavior rather than speed-driven coverage. The code is functionally sound (tests would have caught most symmetry or gating bugs). But it ships with a large volume of plan-process leakage that prior reviews and CONTRIBUTING explicitly forbid. File-by-file stripping of plan references (and any remaining 0008 ones) must happen before merge, exactly as the rule states. Once cleaned, this would be a strong landing.

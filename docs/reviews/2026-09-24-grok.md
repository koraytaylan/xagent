## Findings

### F1 — Predictor step crosses death

**Disposition:** fixed

**Evidence.** `kernel_tick.wgsl:861` calls `agent_death_respawn` and `kernel_tick.wgsl:881` runs `brain_tick_inner` in the same cycle. Before this diff that death path wrote `O_PREV_HOMEO_PREDICTION = 0.0`. Stored predictions are clamped to ±`MAX_HOMEOSTATIC_DELTA` (`common.wgsl:547`, value 0.3), so 0 is a legal model output. The weight update multiplies that error by `O_PREV_PREDICTION` (`brain_passes.wgsl:1264`), which death does not clear. The respawn tick therefore trained the head as if it had predicted 0 from the previous life's features. Before this diff `phase_death.wgsl` had no write of that slot. Invariant broken: an episodic prediction must not be paired with the next life's gradient.

**Fix.** Birth and `reset_agents` both go through `init_brain_state_for`, which writes the absent sentinel into `O_PREV_HOMEO_PREDICTION` (`buffers.rs:859`). The following line (`buffers.rs:860`) is the bias, and that one is `0.0`. `GpuKernel::new` (`gpu_kernel.rs:1018`), `reset_agents_with_rng` (`gpu_kernel.rs:719`, used by `reset_agents` at `gpu_kernel.rs:684`), and `try_reset_agents` (`gpu_kernel.rs:3019`) do not write the slot again. Both death paths store the sentinel too: `kernel_tick.wgsl:686` and `phase_death.wgsl:172`. The brain tick trains and blends only when `homeo_prediction_was_made` (`brain_passes.wgsl:1051`, used at `brain_passes.wgsl:1229`). The layout comment at `buffers.rs:119` now matches `mutate_brain_state_with_rng`, which does not perturb these weights.

### F2 — Parallel Vulkan devices segfault the loader

**Disposition:** fixed

**Evidence.** The baseline `cargo test -p xagent-sandbox` log records `EXIT_FMT=0`, `EXIT_CLIPPY=0`, and `EXIT_TEST=101`, ending with `signal: 11, SIGSEGV` in the integration binary. A debugger stopped that process in `libvulkan.so` inside `vkSetDebugUtilsObjectNameEXT`, stack `auxiliary_steering_loss_converges_on_bearing` → `GpuKernel::read_agent_telemetry_blocking` (`crates/xagent-brain/src/gpu_kernel.rs:3072`), with other threads inside `libvulkan_radeon.so`. The same tests pass one at a time. `XDG_RUNTIME_DIR=/run/user/1000` still segfaults at `--test-threads=4`.

**Fix.** `vulkan_gate::enter` (`crates/xagent-brain/src/gpu_kernel.rs:512`) and `vulkan_gate::stash_for_struct_drop` (`crates/xagent-brain/src/gpu_kernel.rs:530`) serialize Vulkan calls made by `GpuKernel`, including destruction. `poll_wait` is `crates/xagent-brain/src/gpu_kernel.rs:623`. The bench calls it at `crates/xagent-sandbox/src/bench.rs:321` and `bench.rs:692`. This does not cover the window renderer.

**Tests that passed** in `crate-tests.log`: `parallel_gpu_devices_complete_a_dispatch_and_readback ... ok`. The suite that segfaulted, `cargo test -p xagent-sandbox`, exited 0 in `gates.log` (`test result: ok. 114 passed; 0 failed`). Those runs create `GpuKernel` devices only.

### F6 — Renderer and simulation worker are two Vulkan devices

**Disposition:** deferred

**Evidence.** `crates/xagent-sandbox/src/main.rs:267` builds `Renderer::new`, which creates a wgpu device at `crates/xagent-sandbox/src/renderer/mod.rs:201`. `crates/xagent-sandbox/src/gpu_orchestration.rs:103` then starts `SimRuntime`, whose worker calls `GpuKernel::new` at `crates/xagent-sandbox/src/sim_runtime.rs:380` on another thread. The frame loop keeps submitting on the renderer while the worker submits on its kernel. `vulkan_gate` locks only `GpuKernel`. The gate comment that said production has one device was wrong and has been removed. Holding one lock across the renderer's surface acquire and the worker's dispatch was not done: the frame loop was not run here, and a lock that spans present can stall the worker for a whole frame. The sandbox suite never constructs that pair, so a green `cargo test -p xagent-sandbox` does not close it.

**Passed in `crate-tests.log`:** `parallel_gpu_devices_complete_a_dispatch_and_readback ... ok`. That test does not construct `Renderer`, which is why this overlap stays deferred.
